## 1. 项目概况

`dict_ner` 是一个从非结构化中文文本中识别地名/机构名/POI/品牌名的系统。四个模组基于同一 Viterbi DP 引擎，各有独立词典。

| 维度 | 数值 |
|------|------|
| 总代码行数 | ~3,400 行 Python |
| 源文件数 | 25 个 .py 文件 |
| 模块数 | core, loc, org, poi, brand, geomodel, tools (7个) + 根目录脚本 |
| 词典大小 | ~40MB (4个 .pkl) |
| 全量数据 | ~18GB |
| 识别速度 | ~15K rec/s (单核) |
| Python 版本 | 3.10+ |
| 第三方依赖 | 无 (纯标准库) |

## 2. 模块清单与审计结论

| 模块 | 文件数 | 代码行 | 审计结论 |
|------|:---:|:---:|------|
| `core/` | 2 | 213 | 类型定义清晰，但存在命名不一致(LOCATION_SUFFIX_MAP 是 set 非 dict)、硬编码的庞大数据映射、未使用的枚举值 |
| `loc/` | 4 | 833 | 地名识别核心，DP+Trie 设计合理，但存在重复后缀合并逻辑、魔法数字泛滥、Location 后缀被搜索两次 |
| `org/` | 2 | 480 | 机构名识别核心，467行主逻辑功能完整，但存在文件资源泄漏、属性竞态、废弃参数、打印式日志 |
| `poi/` | 2 | 20 | 极简封装(19行)，路径硬编码、版本号默认值脆弱、缺少类型注解 |
| `brand/` | 2 | 171 | Bigram 品牌模型，功能可用但缺少错误处理、训练方法存在代码重复、pickle 加载无安全防护 |
| `geomodel/` | 2 | 5 | 纯导入转发层(5行)，有 wildcard import 反模式，实质无用 |
| `tools/` | 9 | 1,101 | 训练工具集，org/poi 之间存在 ~80% 代码重复，缺少共享配置模块，子进程失败不抛异常，版本号不一致 |
| 根目录 | 3 | 369 | pipeline/CLI/评估，eval.py 存在崩溃级 Bug (NameError)，run.py 文档版本号过期 |
